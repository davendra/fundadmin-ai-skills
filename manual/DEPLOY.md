# Deploying the manual

The manual is published at **https://help.fundadmin.dev** from the Vercel project
`fundadmin-help`, which is Git-connected to `davendra/fundadmin-ai-skills` with
**Root Directory `manual`**. Every `tools/publish_plugin.sh` push to that repository
triggers a production build, so releasing the plugin releases the manual.

Do not edit anything under `manual/` in the published repository: it is
regenerated from `tools/plugin/manual/` in `davendra/fundadmin-ai` on every release.
The command pages, `agents.md`, `guide/outputs.md`, `guide/samples.md` and
`.vitepress/meta.json` are generated by `tools/plugin_docs.py`; the rest is copied.

## Local preview

```bash
python3 tools/build_plugin.py          # regenerates plugin/manual/ (node_modules survive)
cd plugin/manual && npm ci && npm run docs:dev
```

## Manual deploy (fallback)

From a checkout of the published repository:

```bash
cd fundadmin-ai-skills
vercel link --project fundadmin-help
vercel build --prod && vercel deploy --prebuilt --prod
```

Keep the `&&`: `--prebuilt` uploads whatever is in `.vercel/output`, so a deploy after a
failed build silently ships the previous one.

## Project settings that matter

- Framework VitePress, build `npm run docs:build`, output `.vitepress/dist` (from `vercel.json`).
- **Ignored Build Step: always build.** The repository has one squashed commit per
  release, so Vercel's default `git diff HEAD^` check cannot run.
- `lastUpdated` is off in `.vitepress/config.ts` for the same reason; the footer shows
  the plugin version and release date from `meta.json` instead.
