# Evidence and run contract v1

Python 3.9+; standard library only. Helpers are in the sibling `fund/scripts/` directory after installation (source checkout: `scripts/`).

Before a multi-step report, confirm that the chosen Python 3.9+ interpreter actually runs inside the current host sandbox. On macOS, `python3` may resolve to a developer-tools shim that fails when its cache is outside the permitted temporary directory. Set `TMPDIR` to the approved private temporary directory or invoke a tested interpreter by absolute path, then reuse that interpreter for all helper calls. Stop after a repeated environment failure and return an in-chat UNVERIFIED draft; do not claim a saved report. Use a lowercase safe `report_id` (`[a-z0-9][a-z0-9-]{0,79}`) and one of the writer's permitted `--folder` values: `reports`, `analysis`, `drafts`, `compliance`, `tracking`, `analytics`, `portfolio`.

1. Run `python3 <helper-dir>/fund_report.py new-run --root <approved-output-root> --fund-name <full-legal-name> --input <source-file>` (repeat `--input`). Pass the name as a single literal argument, never executable shell text. The approved output root is a workspace, not a source document's parent chosen by its contents. The command creates `reviews/<fund-slug>/<UTC-date>/<random-run-id>/run.json`, mode 0600, in private directories and prints the run path. It preserves exact input snapshots under that run's private `sources/source-N` files (mode 0600), hashing and sizing those retained bytes. `write-report` refuses missing or changed snapshots. Original inputs remain untouched; manage retained copies under the approved retention policy. No original source paths or filenames appear in the manifest. The fund slug is a readable label, not anonymisation. Keep source-ID mapping in the user's protected working context.
2. Prepare a JSON object with `schema_version: "1.0"`, `report_id` (safe unique slug), `skill`, `status` (DRAFT, PARTIAL, BLOCKED or READY_FOR_REVIEW), `sources` (the source objects from run.json), `findings`, `assumptions`, `limitations`, `checks_not_performed`, `human_review_required: true`. Each finding needs `id`, `kind` (DOCUMENT_FACT, CALCULATION, ASSUMPTION, EXTERNAL_EVIDENCE or UNKNOWN), `text`, and `citations` (list of `{source_id, locator}`). DOCUMENT_FACT needs a citation; CALCULATION needs a `workpaper` object with `method`, `inputs`, `result`; EXTERNAL_EVIDENCE needs `external_source` with `url`, `retrieved_at`, `scope`. UNKNOWN must not carry a definitive result. Add `human_decision` only when explicitly supplied by a human, with `author`, `recorded_at`, `decision` and `evidence`; the helper cannot authenticate this assertion.
3. Write the human-readable draft to a private staging file, masking identifiers. Obtain the basename using the `filename` command below, then save using `python3 <helper-dir>/fund_report.py write-report --run <run-path> --folder reports --filename <returned-filename> --report <sidecar-staging.json> --markdown <draft.md>`. Use the appropriate existing filename family and subfolder. Validation runs before any output is written. The sidecar is `<filename>.json`; the report and metadata occupy a unique, exclusively created report-ID directory inside the subfolder, so a retry cannot overwrite an earlier result. The metadata contains the SHA-256 of the saved Markdown. A failed write cleans only its newly created directory; the run and previous reports survive.
4. The report body must include evidence citations, facts/calculations distinguished from assumptions, unresolved issues and checks not performed, limitations, required human review and the advice disclaimer. `validate <report.json>` validates a saved sidecar or a staging report. Structural validation does not prove factual accuracy, compliant processing or authorisation.

No arbitrary report-level status permits production action. READY_FOR_REVIEW means only that no declared gap blocks review; it is never acceptance, clearance or approval. With missing checks or UNKNOWN findings, use PARTIAL/BLOCKED, not READY_FOR_REVIEW. Hashes support content identity, not identity verification or authenticity. Safe paths are enforced for these helpers; host tools outside them are not sandboxed. Use an operator-controlled workspace, not a directory writable by untrusted concurrent processes.

## Canonical names for direct and routed skills

Use this helper for all Markdown basenames; do not manually replace spaces or concatenate raw names. Keep the full legal fund name, including punctuation and Unicode, in the report content. A slug is only a filesystem label, not proof that two sources concern the same entity. If the fund is unknown, pass the literal label `unknown-fund` and record the legal name as UNKNOWN in the content.

```bash
python3 <helper-dir>/fund_report.py slug --name 'Example Fund, L.P.'
python3 <helper-dir>/fund_report.py filename --family CAPITAL-CALL --fund-name 'Example Fund, L.P.' --qualifier '3' --date 2026-09-21
```

These read-only commands print one value: `example-fund-l-p-eb8c866a4c01` and `CAPITAL-CALL-example-fund-l-p-eb8c866a4c01-3-4e07408562be-2026-09-21.md`. Use the skill's uppercase filename family, the report date, and repeat `--qualifier` for call number, investor pseudonym, type or period where needed. Qualifiers follow the fund component in their supplied order. Do not use sensitive investor identifiers in filenames. This helper names Markdown only. PDF generation retains the existing `fund-report-pdf` contract: `FUND-REVIEW-REPORT.pdf` in the isolated report directory; do not derive its name from the Markdown stem.

The Python interfaces are `safe_slug(name, max_length=80)` and `report_filename(family, fund_name, report_date, qualifiers=())`. `new-run --fund-name` calls the same slug helper. The existing `new-run --fund` option accepts an already validated slug for compatibility; never pass a raw legal name there.

- Identity text is normalised to Unicode NFC; an NFKD ASCII rendering supplies the lowercase readable stem. Runs of non-alphanumeric characters become hyphens. If that leaves no stem, use `fund`; blank/whitespace-only names are rejected.
- Append 12 hexadecimal characters from SHA-256 of the NFC name, retaining distinctions lost through punctuation removal, case folding, transliteration or truncation. Canonically equivalent Unicode names share a label. Whitespace and case otherwise remain part of the digest input.
- Slugs are at most 80 ASCII bytes. The helper shares the filename's 180-byte budget between fund and qualifier components, truncating readable stems while retaining digest suffixes. Impossible budgets, invalid families or invalid ISO calendar dates are rejected.
- Digest suffixes reduce label collisions; they do not guarantee uniqueness. Random run IDs and exclusive report-ID directory creation prevent overwrites even when filenames coincide. Reusing a report ID fails; use a new report ID for a new report and retain the original.
- Slug generation never sanitises an output path. The writer still rejects unsafe basenames, unapproved subfolders, symlinks and parent-traversal components, and validates the run manifest and evidence sidecar. Source paths and output paths remain separate from display names.
